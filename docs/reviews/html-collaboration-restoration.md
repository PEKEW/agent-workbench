# HTML 协作恢复检查

## 问题与修复

阶段一 UI 漏掉了原 HTML-for-LLM 的讨论面板与批注交互，工作台只剩文件阅读和编辑，偏离了项目目标。本次恢复文件导航、正文、批注与讨论三栏，以及文字引用、备忘日期、普通回复／Rebuttal／结论、解决／重开、删除与 JSON 交接。原文编辑、工程文件折叠和 Archify iframe 保留。

讨论改由本地服务保存到 `.agent-state/collaboration.json`，首次明确保存才创建；打开、读取与导出不生成文件。generation 防止同一服务内旧标签页覆盖新讨论；冲突保留输入，只读加载新状态，核对后再保存。项目移动后保留已有工作区 ID。正文变化后保留引用及讨论，并提示定位失效或存在多处匹配。

导入兼容 agent-docs-feedback v1，重复回复跳过、相同 ID 不同内容拒绝；完整交接包合并讨论而不恢复磁盘正文。正文建议先进入待处理讨论，由人工原文编辑保存采纳。这是接入真实项目文件后的明确行为变化，导入预览有说明。冻结讨论证据未改动。

## 验证

Go 测试覆盖讨论持久化、服务句柄重开、项目移动、内容版本、旧 generation 冲突、非法路径与角色、符号链接拒绝、接口认证及 Origin 限制。

真实 Chrome 验证文字选择批注、消息转义、Rebuttal、解决／重开、备忘与筛选、回复导入幂等、修改建议不覆盖正文、冲突输入保留与重试、删除、刷新和服务重启后恢复、正文变化引用提示，以及原文编辑、文件折叠、只读打开、iframe 隔离和窄屏布局。截图见 stage-one-collaboration.png，结果见 stage-one-browser.json。

## 范围限制

Agent 署名和手动交接不能代表 CLI 已连接；会话控制、任务分配、自动消息转发和运行日志仍待原生适配。状态写入通过同目录临时文件替换，不提供多个服务进程或外部工具同时写状态文件的事务保证。完整交接正文上限 16 MiB，讨论状态上限 16 MiB；超限导出明确报错，不阻止文档阅读。
