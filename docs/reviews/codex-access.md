# 阶段二 Codex 接入检查

## Correctness

CLI connect 和网页创建均通过真实 stdio app-server 入口建立新会话。工作目录固定为项目，模型留空沿用本机配置；权限展示原生返回值。工具仍由 Codex 执行，不从网页透传任意 shell 或 RPC 方法。

握手、消息 ID、原生错误、超时与退出、忙碌排队、失败／中断暂停、审批一次响应、撤销后不能批准、子 thread 不影响主 thread 生命周期、历史恢复和日志补读均有 Go 测试。临时项目真实模型回合执行 shell 读取 PLAN.md，命令输出及 agent 回复包含预期标记。服务恢复不自动重发未知结果输入。

## Design

internal/agent 分为协议客户端、会话管理、请求响应和受限日志存储。HTTP 固定接口与项目上下文预览在 internal/server，项目状态目录使用 os.Root。网页增加会话视图，原三栏阅读、编辑、批注、备忘、JSON 交接与 Archify iframe 保留。

同一会话只有工作台输入入口；本阶段不接管现有 TUI，不声称取回终端控制权。任务输入不等同于完整的任务管理系统；多 agent 讨论当前复用现有批注、逐次预览并人工转发，不自动广播。

## Complexity

Go 标准库实现，运行不依赖 Node.js、外部队列、数据库或通用 agent 框架。每会话独立 stdio 进程，最多同时 8 个，队列最多 20 条。完整日志保留磁盘，界面近期事件与完整原始日志分别可读。原生不支持的请求不自动生成工具结果。

## Tests

Go race、vet、构建及 Markdown 检查通过；前端 Node VM 回归验证切换会话的事件归属及发送期间新草稿保留，以及完整日志跨会话游标重置与旧请求隔离。真实 Chrome 集成使用标明身份的独立协议测试进程，验证专用命令、会话视图、上下文预览、任务发送、执行事件转义、讨论往返转发、排队／中断／继续、命令审批、问题回答、轮询后焦点保留、权限拒绝、完整日志、网页重载与显式恢复、窄屏布局。原阶段一交互与 iframe 隔离回归全部通过。

截图为 stage-two-agents.png、stage-two-approval.png、stage-two-mobile.png；浏览器结果为 stage-one-browser.json，其中 codexProtocolFixture 明确区分测试进程与真实 CLI。真实 CLI 与模型验证由 real_codex_test.go 的显式环境开关运行，不混入一般测试、不伪造模型结果。

## Maintainability 与审查修正

独立审查确认三个重要问题并修复：关闭只杀父进程会遗留继承 pipe 的后代；会话切换期间 await 使用错误 ID 导致日志串写；发送成功清空用户期间新输入的草稿。均补失败到通过的测试。

此外补上中断立即撤销审批资格及写入前有效性复核、原生子 thread 生命周期过滤、轮询保留问题输入焦点、日志展开状态保留，以及 isSecret 回答日志遮蔽。完整日志切换会话会重置分页并即时读取新会话，旧响应及 finally 不干扰新请求。测试使用真实子进程、受限目录和原前端函数。未修改冻结讨论证据。最终独立复核无剩余重要或阻断问题，三个前端并发回归测试通过。
