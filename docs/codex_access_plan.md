# Codex 接入实施计划

> 执行方式：使用 executing-plans，在当前分支逐项实现；沿用用户授权，不创建默认 worktree。

目标：将新的 Codex 原生会话接入现有工作台，完整保留文档与讨论。

架构：标准库 Go 管理 stdio JSONL 协议、会话与日志；本地 HTTP 路由负责选定上下文；原生运行时执行工具；网页独立会话视图呈现状态与响应。

规格：`docs/specs/codex_access_spec.md`。

## 约束与检查重点

- 不修改冻结讨论证据，不联网下载运行依赖，不读取认证文件。
- 输入入口串行；启动与超时失败不自动重放；权限取原生返回值。
- 路径与会话引用、原生请求 ID、输入大小、退出和服务恢复均需验证。
- 日志只记录实际观察到的事件；关闭仅管理自有子进程。
