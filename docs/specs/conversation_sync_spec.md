# 对话展示与讨论增量同步

## 状态与目标

已按用户授权和书面计划实现，验证见 docs/reviews/conversation-sync.md。依据 PLAN.md 上的讨论 ca409b63-d561-4a6b-a415-6f85406bb592：改善 Agent 对话阅读，自动关联文档讨论，并减少重复上下文。采用现有 Go 服务、前端 Markdown 依赖和 JSON 持久化，不引入 SQLite。

本规格替代 codex_access_spec.md 中模型文本纯文本展示、讨论逐次手动全量转发和回复手动回写的相关约定。原生权限、审批、显式会话恢复、项目目录约束与输入上限保持适用。

## 两条时间线

Agent 页展示对话和执行过程两条同步时间线。宽屏并列，窄屏上下排列，各自保留滚动位置。对话包含用户实际输入、Agent 中间消息、流式回复及最终回复；执行过程包含命令与输出、文件修改、工具事件、诊断和回合结果。审批入口继续独立显示。对话与执行为主区域，压缩侧栏、状态栏及输入区，发送预览默认折叠；宽屏验证主区域高度超过视口 55%，宽度超过 65%。

两条时间线使用同一事件源，按会话、原生回合 ID 和事件序号关联，提供定位同回合的操作。用户输入只显示一次；排队状态转换为执行状态时更新原条目。流式消息按 item ID 更新，完成消息替换同一条目，不重复追加。输入所附的文档和讨论材料折叠显示，用户可以检查实际发送内容。

每条时间线分别展示最近 100 条对应记录，执行事件数量不能挤出对话消息。完整日志入口继续按事件序号补读；网页重载可以重建两条时间线。时间线只展示接口实际提供的信息。

## Markdown 展示

用户消息、Agent 消息和文档讨论正文复用 marked 与 DOMPurify，支持段落、标题、强调、列表、引用、链接、代码、表格及 LaTeX 公式。公式由 marked-katex-extension 解析 `$...$` 行内与 `$$...$$` 块级语法，KaTeX 在浏览器端渲染；KaTeX 脚本、样式和字体全部由本地服务提供，不加载远程资源。输入框、发送预览、执行日志、审批参数和原始 JSON 保持纯文本。

渲染关闭原始 HTML，过滤危险链接和事件属性；代码块中的 HTML 按代码显示。消息不加载远程图片。清理白名单在原有标签之外仅放行 KaTeX 输出使用的标签与属性；原始 HTML 在进入清理前已被转义，不能借公式白名单进入文档。项目内 Markdown 链接沿用阅读器导航，外部链接采用安全协议和新窗口关系属性。解析或清理失败时退回纯文本；公式语法错误按红色文本显示原始公式，KaTeX 组件缺失时公式按纯文本显示。

存储、复制和转发保留 Markdown 原文。流式渲染使用同一安全规则，最终以完整原文重新渲染。渲染函数不依赖当前文档全局变量，供三个展示位置共用。

## 工作会话、讨论与参与会话

工作会话负责项目任务；文档讨论保存引用、发言和结论；每个参与 Agent 在每份文档上使用一个讨论专用会话，该文档的全部批注与备忘由同一会话处理。讨论专用会话保存 parentSessionId 和 documentId，采用现有 thread/start 创建独立原生上下文。父子关系由工作台管理，不继承工作会话完整历史，不声称使用了原生 subagent 调度。

从讨论选择一个工作会话作为参与 Agent，明确启动或打开该参与者在该文档上的讨论专用会话；同一父会话与文档复用同一专用会话，同一文档的不同讨论不再各自创建会话。不同文档对应不同专用会话。专用会话继承父会话的模型配置、沙箱和审批策略，均计入最多 8 个运行时会话。恢复仍须用户明确操作。父会话关闭不删除讨论或子会话记录。按讨论建立的旧会话在载入后视为其所属文档的讨论会话；其旧同步记录不作为增量基线，下次发送完整材料。

讨论入口自动载入专用会话和文档讨论面板，任务指令、引用和发言在发送前预览；正文仅在用户主动勾选时附带。讨论消息提交只保存发言，不自动触发模型回合；用户预览并发送后启动处理。每次发送明确列出本回合需要回应的讨论：从单条讨论进入时为该讨论，批量交付时为所选讨论，未指定时为该文档全部待处理讨论；文档没有待处理讨论时拒绝发送。每个回合固定归属该专用会话的文档，切换文档不改变归属。

首次关联或换原生会话时发送所列讨论的完整快照，包含引用与发言，不默认发送整篇文档；后续只发送所列讨论中新增、修改或删除的消息及变化的引用，没有变化的讨论只列出标题。已送达后被整条删除的讨论在下次发送时注明已删除。正文须主动勾选；仅首次选择、版本变化或明确完整重发时附带。未勾选时保留先前已送达正文的版本，避免重新勾选后重复发送。来自同一专用会话的未修改回复跳过，其他参与者的回复正常发送。引用保留原文与版本，正文变化不自动改写引用。

预览显示全量或增量及实际材料，可选择完整重发。只依据已确认送达的记录计算增量；排队输入保存不可变快照且不推进基线，可能重复附带尚未送达的材料，以保证前序失败或清空后背景完整。依赖未确认送达的输入不会被用作增量基线。

工作会话只接收用户明确选择的讨论结论与依据，提供“送回工作会话”预填与预览入口，明确发送后才执行。自动读取和回写讨论不向父会话或其他参与者自动广播。

## JSON 记录

在现有 `.agent-state/sessions/<sessionId>/state.json` 中增加讨论关联和同步记录，在输入记录中保存上下文快照及目标。继续沿用受项目根目录限制的文件操作、符号链接拒绝、临时文件替换和服务内互斥。不另建数据库。

每个讨论专用会话的已送达记录包含原生 thread ID、文档路径与 SHA-256、对应输入和回合 ID，以及按讨论 ID 保存的引用哈希和消息 ID 到内容哈希的映射；输入快照另记本回合需要回应的讨论 ID 列表。消息哈希覆盖署名、角色、意图和正文，按讨论顺序生成输入。旧会话文件缺少新字段时视为未同步，首次发送完整材料。

讨论消息增加可选的结构化来源：工作台会话 ID、原生 thread ID、turn ID 和 item ID。该来源用于跳过自身回复与回写去重，不解析正文中的来源说明来推断状态。旧的手动转发来源文字继续作为普通正文保留。

预览和排队不推进已送达记录。排队输入保存已预览的不可变快照，只依赖已确认基线。原生送达结果不明时暂停队列，显式恢复后重新预览；讨论输入使用完整重发恢复基线。

发送接口接收预览标识与版本信息，由服务验证目标、讨论版本和同步基线，拒绝过期预览并保留用户草稿。调用原生 turn/start 成功返回或收到匹配的 turn/started 后，才能确认该输入已送达。事件早于响应时仍按同一输入登记一次。回合失败或中断不撤销已确认送达的材料。

结果不明时保持未确认状态，暂停后续依赖发送，提示检查原生历史并重新预览完整材料；不自动重放。服务重启沿用显式恢复规则，不自动发送旧队列。改变原生 thread ID 后，原送达记录不作为新会话的增量基线。

## 回复回写

本地服务负责同步，网页轮询只刷新显示。关联回合的最终回复在完整 item/completed 到达且回合 completed 后回写；中间消息、工具输出和流式片段只留在会话。若接口不提供可区分的最终消息标记，取该回合最后一条完整 Agent 消息，并保留完整会话记录。

回写按输入快照中需要回应的讨论分配最终回复。本回合只列出一条讨论时，整条回复写回该讨论；列出多条时，输入要求 Agent 以「### 讨论 <ID>」标题逐段回应，服务按标题把各段写回对应讨论，标题前的内容和未列出 ID 的标题不单独回写。多条讨论的回复缺少可识别标题时，不猜测归属，回复保留在会话中并提示未自动写回，用户可手动加入讨论。回写记录结构化来源，默认意图为普通回复。以原生 thread ID、turn ID、item ID 和讨论 ID 去重；重复事件、重载和重试不追加重复消息。人工手动回写采用同一去重规则，允许另建有明确新 ID 的补充意见。

讨论状态更新按最新 generation 合并追加，避免覆盖人工新消息。回写成功后登记同一会话已知的回复 ID 与哈希。跨文件更新不能宣称具有数据库事务保证：先持久化待回写记录，再幂等追加讨论，最后标记完成。启动时只恢复待回写操作，不启动模型回合；扫描完整日志补齐已完成回合遗漏的回写记录。

讨论已删除时保留回复在会话中，不重建讨论；回复涉及的讨论全部删除时提示未同步，部分删除时其余讨论照常写回。保存失败保留待回写状态和具体错误，可重试。同步失败不能改变原生回合结果。自动回写不覆盖项目正文，不向其他 Agent 自动广播，不自动标记讨论解决。

## 实现顺序与验收

书面实现计划见 docs/conversation_sync_plan.md。实现依次完成共用 Markdown 与两条时间线、输入关联与 JSON 记录、增量发送与队列约束、服务端回写及恢复。各阶段保留现有审批和文档操作回归。

验收场景：

1. D-C1 首次发送后回写 R1；同一会话第二次仅发送 C2 和变化材料，不重复发送 D、C1、R1。换会话后完整发送 D-C1-R1-C2。
2. 同一工作会话参与同一文档的两条讨论，共用一个专用会话，一个回合内按标题分段的回复分别回到各自讨论；参与不同文档时使用不同专用会话；关闭网页后仍回写，重新打开后看到结果。
3. 新消息、消息内容变更、删除、主动选择的正文修改、其他会话回复及完整重发均生成符合预览的输入；过期预览被拒绝。
4. 排队、前序失败、队列清空、响应丢失、重启及 thread ID 改变不会把未送达材料记为已送达，也不会自动重放模型任务。
5. 事件重复、回写失败重试和跨文件保存中断后不丢消息、不重复追加、不覆盖人工消息；讨论删除后保持删除状态。
6. 两条时间线回合关联正确，输入和流式回复不重复；大量执行事件不挤出对话，完整日志可补读。
7. Markdown 基本语法可读；脚本、事件属性、危险链接和远程图片不执行或加载；复制的原文不变。
8. 运行 Go race 测试、vet、build、Markdown 检查及相关浏览器测试，实际检查截图，并将结果保存到 docs/reviews/。

## 中止条件

若原生协议不足以确认输入归属和送达状态、无法关联回复回合，或 JSON 更新无法保留冲突与待回写状态，则暂停相关同步步骤并报告；不以猜测来源或自动重放代替确认。

## 批量按文档交付

批注可多选，跨文档保留选择；全选只针对当前筛选可见项。统一选择工作会话与任务要求后，所选讨论按文档分组，每份文档创建或复用一个讨论专用会话，并生成一次包含该文档全部所选讨论的预览，预览不发送任务。明确点击批量发送后，仅提交已成功预览的文档，每份文档只启动一个回合，返回结果按文档展示；回复由后台按讨论标题分别写回。按文档合并减少同时运行的会话与并发请求。

默认不附正文，沿用每个专用会话的增量基线、运行时最多 8 个会话及现有审批。单份文档预览失败不妨碍其他文档预览。已经交付或发送报错的项目不自动重发；送达结果可能不明时提示检查对应会话。关闭批量窗口后，任务继续由服务执行，会话和讨论保存完整结果。此入口不另建持久化任务调度器。

## 执行状态可见性

顶部跨视图显示会话执行、等待与空闲汇总；Agent 页和批注中的参与会话显示明确状态，可进入对应会话查看执行。日志读取失败不得阻止已获取的会话状态刷新；会话接口连接失败时明确标为状态未同步，避免把旧状态作为当前状态。

讨论任务默认保留最新用户发言作为任务要求；用户要求实现或修改时，应实施并验证。批量任务处理所列各条讨论中的最新要求，不使用固定的仅讨论指令覆盖用户意图。回合完成仅表示原生回合结束，不代表功能验收完成。
