# 阶段一 项目新建与恢复

## 范围

Go 实现 CLI、本地 HTTP 服务、模板初始化和文档读取。静态网页与模板内嵌到可执行文件。一个进程绑定一个项目；打开后不能换绑，打开另一项目需启动另一进程。此阶段提供文档阅读、编辑、保存和刷新，不实现 agent 接入或终端接管；文档协作能力保留原 HTML 的批注、备忘与讨论。

## 命令与流程

`agent-workbench` 启动选择页；`agent-workbench open <目录>` 直接打开已有项目；`agent-workbench new --name <名称> <新目录>` 创建后打开。默认自动打开浏览器，`--no-browser` 只打印地址，`--port` 可指定端口，默认使用空闲端口。Ctrl+C 关闭本地服务。

新建目录的父目录必须存在，目标目录必须不存在，包括空目录和符号链接。保留原创建器复制模板与替换参数的行为，以 Go 实现；嵌入固定模板，不联网下载。项目名非空、最多 100 个字符且不得包含控制字符。配置通过 JSON 编码写入，支持引号与中文。

已有目录的打开操作只读加载；明确保存编辑时才写回文件。有效 project.json 或 semi-harness 标志文件／目录用于识别；缺项与配置格式问题展示为提示，仍可阅读。完全无关的目录拒绝打开。打开不执行项目脚本、不生成文件、不修改 Git 状态。

## 文件与界面

左侧按项目相对路径列出根目录 Markdown 和 docs 下 Markdown；同名文件保持独立。默认打开 PLAN.md，其次 README.md。显示项目名、根目录、缺项提示，支持过滤、刷新、渲染阅读和原文切换。文档渲染关闭原始 HTML，链接不触发脚本，项目内 Markdown 链接在阅读器打开。

只读取普通 Markdown 文件，不跟随文档符号链接，不读取根目录以外文件。单文档上限 2 MiB；最多 2000 份文档，超出时提示。打开文档时使用受项目根目录约束的文件访问，并再次校验文件类型和大小。文件删除或修改后返回最新结果或明确错误。

## HTTP 接口

接口返回 JSON；错误格式为 error 字符串。GET /api/project 返回项目或 null；POST /api/project 接收 action（new/open）、path、name；GET /api/document?path=项目相对路径 返回 path、markdown、revision 与 editable；POST /api/document 保存现有文档。无项目时读取文档返回冲突；重复绑定返回冲突；非法路径或输入返回错误。

只监听 127.0.0.1。每次启动生成随机令牌，通过 URL fragment 交给网页；API 请求使用 X-Workbench-Token。拒绝外部 Origin 与无令牌访问，响应禁止缓存。令牌不写入项目，不放进查询参数。服务关闭后 URL 失效。

## 实现布局

cmd/agent-workbench：命令、监听、浏览器启动和退出。
internal/project：创建、识别、文档索引与受限读取；template 为固定模板。
internal/server：HTTP 接口与单项目绑定；web 为网页资源。

Go 模块采用标准库处理文件、HTTP 与 JSON；Markdown 渲染复用经核对的现有页面资源或引入单一渲染依赖，避免自行编写不完整解析器。

## 验收

新建目录内容正确且不覆盖已有文件；中文、引号与空格路径可用；重复打开不能换绑；已有项目打开及阅读前后文件字节与 Git 状态不变；缺项可见；两个 README 路径独立；越界、外部符号链接、伪造网页请求被拒绝；恶意 Markdown 不执行脚本；网页完成新建和打开两种流程。

## 独立图嵌入

用户指定采用 iframe。项目可在 docs/diagrams/ 保存 Archify 独立 HTML 与 JSON 源，网页增加图列表；无图时不显示此入口。GET /api/diagram?path=相对路径 经过同一令牌验证后返回 HTML，网页用 sandbox=allow-scripts 的 iframe srcdoc 显示。图不能访问父页面、弹窗或调用本地接口；不接生成服务、不做双向编辑。生成工具仅供开发时使用，运行工作台不依赖 Node.js。

为支持独立 HTML 的内联脚本与样式，页面 CSP 允许内联资源；Markdown 始终过滤脚本与事件。iframe 在最前方注入独立 CSP，禁止网络、表单和外部脚本；保留本地图的节点交互。图内下载、弹窗或需要联网的功能不在此嵌入版本范围内。

## 文档显隐与编辑

默认展示计划、设计、发现、评审与交互图。AGENTS、CLAUDE、第三方说明、规范、规格模板和开发检查报告默认收进“工程文件”；用户可展开或通过文档链接主动打开。文件仍在项目中，隐藏仅影响网页导航。

文件导航按项目内的真实目录分层显示，目录在前、文件在后，同级按名称排序；“工程文件”使用同样的目录结构。目录可折叠，展开状态按项目保存在本机浏览器，存储不可用时默认只展开 docs。打开文档时自动展开其所在目录；筛选时展开所有包含匹配项的目录，清空筛选后恢复用户的展开状态。

Markdown 增加编辑原文、保存和取消。读取返回内容 SHA-256 版本；保存要求携带读取版本，版本不匹配返回冲突且保留草稿。先在同目录写临时文件，再替换原文件，保持文件权限；只保存已存在的 Markdown，禁止越界、符号链接、只读区域和冻结讨论目录。保存不自动提交 Git。切换文档、刷新或关闭时提示未保存内容。

Archify 当前由外部 agent 修改 JSON 源并生成 HTML；工作台刷新读取成品。未来 agent 接入后采用明确“更新图”请求作为主触发，设计或阶段计划变更后可提示图可能需要更新，普通文档保存不自动重画。此版本仅说明更新方式，不添加后台生成服务。

## HTML 协作恢复

恢复三栏工作台：文件导航、正文阅读／编辑、批注与讨论。支持同段文字引用批注、整篇批注、备忘日期、署名与 human／agent 角色、普通回复／Rebuttal／结论、解决与重开、删除讨论、类型与状态筛选。引用失效或存在多处匹配时保留原引用并提示，不猜测新位置。

讨论按文档相对路径关联，保存在 `.agent-state/collaboration.json`；GET 只读，首次显式保存时创建。文件采用临时文件替换， generation 检查避免同一服务的多标签页互相覆盖。目录或文件为符号链接时拒绝访问。所有接口沿用令牌与 Origin 验证。状态大小上限 16 MiB；打开文档的能力不依赖全量交接包大小。

保留 agent-docs-workspace v1 JSON 导出、agent-docs-feedback v1 回复导入。导出正文从项目读取，文档 ID 为相对路径，整数 revision 由内容哈希跟踪。导入只合并相同工作区的讨论与回复，重复 ID 的相同内容跳过、不同内容拒绝。正文 changes 作为待人工采纳的修改建议讨论保留，不直接覆盖文件；用户通过原文编辑器采纳并保存。完整交接包导入只合并讨论，不替换项目正文。界面明确显示此边界。

讨论署名和手动交接不代表 agent 已接入。真实 CLI、任务分配、会话控制、运行日志与自动消息转发仍待后续适配。
