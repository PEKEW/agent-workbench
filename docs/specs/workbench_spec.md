# Agent Workbench 产品规格

## 目标与现状

建立以 semi-harness 组织规范为基础的本地网页工作台。当前仅有工程骨架与需求文档，以下描述目标行为。

## 项目边界

一个工作台只绑定一个项目，一个项目内可管理多个 agent、会话、任务和讨论。新建沿用现有 semi-harness 创建器；恢复选择已有项目根目录，读取配置、计划、进度、设计和证据后继续工作。保留已有文件与未提交修改，缺必要文件时明确提示。首期不加入项目注册中心、模板版本管理、升级、迁移或自动修复。

项目可在没有运行中 agent 时打开。项目恢复与原生会话恢复分别表达；读取项目文件不能保证恢复模型内部上下文。

## 文档与规范

specs 保存设计，PLAN 保存当前状态，task_plan 保存长期任务，findings 保存发现，reviews 保存证据。progress 只保留精简进度、里程碑和修正，原始执行日志由本地服务保存。

specs 和 reviews 按原目录独立展示，使用项目内相对路径区分同名文件。Markdown 为正文来源，网页聚合阅读与交互；共用规范供各运行时读取，Claude 专用规则与加载机制单独配置。

## 组件与数据流

网页提交输入 → 本地服务记录并路由 → 适配器调用原生运行时 → 运行时执行文件、代码、shell、Git 与工具操作 → 事件经本地服务返回网页。

模型只接收选定文档、片段、消息或差异。网页 DOM、CSS 和全部历史不默认进入模型上下文。日常读写通过本地服务衔接，导入／导出保留为离线交接与备份。

## Agent 接入与控制权

优先接入 Codex，通过专用命令启动新会话；后续按工具能力支持历史会话恢复、运行中会话移交以及更多 CLI。采用少量原生适配代码与运行时 JSON 配置，原生接口版本在实现时核对。

终端让出日常输入控制权，执行中的任务继续运行。每个会话同一时刻只有一个控制入口，终端可显式取回控制权。网页断线后本地服务继续运行，需要人工响应时等待；重连补齐状态与日志。服务恢复先核对执行状态，不自动重放结果不明的命令。

原生运行时负责工具执行、沙箱和权限约束。网页呈现原生参数、审批、权限跳过模式、插件与 skill 入口，说明配置生效边界；普通聊天不能替代工具审批。

## 任务、Git 与讨论

多个 agent 共享项目目录，人工 diff 审阅后通过 Git 保存版本和处理合并。任务与会话分别管理，用户验收结果；首期不默认引入文件锁、自动合并或独立 worktree。

可以从批注、任务或独立入口拉起讨论，选择参与 agent 与材料并预览后发送。先人工转发观点和 rebuttal，保留作者、来源及回应对象；新消息不自动广播。讨论复用工作会话，agent 按当前原生权限执行操作，事件关联到对应任务或讨论。

忙碌会话默认排队到当前回合结束，追加指示或中断按适配器能力提供。用户采纳结论后选择目标文档、预览变更再应用。关闭讨论、采纳结论与完成写回分别记录。

## 批注操作

支持删除单条发言或整个批注／讨论；支持输入 @ 选择当前项目批注并插入可点击引用。

可恢复删除、删除占位、旧导入防复活，以及发送时保留引用片段和版本属于当前设计建议，具体字段、恢复期限和彻底删除规则待功能规格确定。删除操作不撤销已经执行的命令或文件修改。

## 日志默认口径

每个独立 agent 会话的 shell 与决策分别统计：默认查看最近 100 条；每类未归档原始记录超过 300 条后，归档旧记录并保留最近 100 条。shell 一条对应一次命令及其结果；决策一条对应一次明确采纳的结论。

此为讨论收束时沿用的默认解释，具体配置在实现规格中落实。摘要保留原始引用与修正关系；完整讨论、任务和转发关系不随 shell 轮换删除。只展示接口可观察的操作，不补造日志。

## 首期验收

1. 新目录可通过现有创建流程建立并打开。
2. 已有目录可恢复阅读与工作，原文件和未提交修改保持不变。
3. 没有运行中 agent 也能打开项目，缺项给出明确提示。
4. specs 与 reviews 中同名文件保持独立。
5. 原生会话恢复能力尚未提供时，界面不会声称已恢复模型上下文。

后续分别验证会话控制、断线重连、两 agent 人工讨论、引用和写回。网页代码查看器及编辑器联动留到远期。

## 待定事项

服务语言、网页构建方式、数据存储位置与接口字段尚未选定。产品入口与 Codex 适配均未实现，不以现有讨论 HTML 充当工作台运行版本。
